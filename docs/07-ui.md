# Standing on the Moon: an interface from zero

## 1. Start with a question, not a graph

This interface asks what can reach a fixed landing site at a chosen time. A horizon is the boundary between ground and sky. A direction around the observer is called azimuth; north is 0 degrees, east 90, south 180, west 270, and north again 360. Elevation measures angle above the local horizontal plane, not altitude in meters. One degree is one part of a 360-degree turn. The whole strip shows every direction at once, rather than a camera's narrow view.

The default view has black sky, yellow Sun, blue Earth and opaque grey ground. The Sun's angular radius is 0.267 degrees; Earth's illustrative radius is 0.95 degrees. Angular radius is the angle from the center to the edge, so a diameter is twice that. This is not a photograph: the vertical angle scale is stretched, and its actual multiplier is printed below the strip. In particular, a round disk becomes an ellipse on this nonuniform angular display. The Sun is intentionally very thin on a small screen; its text label identifies the true-sized body instead of secretly enlarging it.

The old egui_plot graph remains under Technical view. It supplies numeric azimuth/elevation axes and current position markers. Its technical terms, loading architecture, time-window arithmetic and wrap splitting are taught in [the panorama guide](05-panorama.md). The globe remains an illustration with its own light and rotation, not the scientific sky at the selected time. No site-selection workflow or new terrain preparation policy is introduced.

## 2. Turn angles into pixels

The scene reserves a rectangle with left edge L, top T, width W and height H. The horizontal field is 0 through 360 degrees and the vertical field is -10 through +10 degrees. For direction A and elevation e:

$$x=L+WA/360, \qquad y=T+H(10-e)/20.$$

Screen coordinates grow downwards, so increasing elevation subtracts from y. The horizontal scale is W/360 pixels per degree; vertically it is H/20. Their ratio is the labeled vertical exaggeration:

$$V=\frac{H/20}{W/360}=18H/W.$$

For a 720 by 180 pixel field, horizontal scale is 2 pixels per degree, vertical scale is 9, and V=4.5. A 0.267-degree radius Sun therefore spans about 1.068 pixels horizontally and 4.806 vertically. The 360-degree strip cannot show its small disk as a giant icon without changing angular scale. All fixed-site data currently fit the vertical field; future sites outside it require a different range, not changes to scientific values.

The disk boundary uses 64 samples of a spherical circle, not a circle of arbitrary screen radius. Reuse core::destination, treating elevation as latitude and azimuth as longitude. Multiply the desired angular radius in radians by the same reference radius passed implicitly by that function; division by that radius inside the spherical formula cancels it. The result is an angular construction independent of lunar terrain elevations. Tests independently recover every boundary point's angular separation using the spherical dot product.

North is a seam in the flat strip. Unwrap each boundary point close to its center with `(a-center+180).rem_euclid(360)-180`, then draw translated copies at -360, 0 and +360 degrees, clipped to the same rectangle. This preserves the two visible pieces of a disk crossing north. Track lines use the existing segments helper, which breaks a path whenever adjacent azimuths differ by more than 180 degrees. No false horizontal chord crosses the sky.

## 3. Occlusion is drawing order

An occluder hides what is behind it. The UI uses a painter, which submits colored shapes in order. Later opaque shapes cover earlier ones. First paint black sky and faint guide lines, then faint time-window paths, then finite Sun and Earth disks, and last grey terrain. Part of a disk below the horizon is therefore genuinely covered rather than merely tinted or outlined.

| Order | What is submitted | C++ rendering analogy |
|:--|:--|:--|
| 1 | Black field and angle guides | Clear a clipped drawing surface |
| 2 | Faint selected-time paths | Submit line strips |
| 3 | Yellow and blue finite disks | Submit filled boundary polygons |
| 4 | Opaque grey terrain | Submit indexed triangles last |

A terrain profile is generally not convex: a line between two hilltops can pass through sky. Passing the whole ground boundary to a convex-polygon fill would be wrong. Instead, construct one trapezoid per adjacent horizon pair and split each into two triangles. Horizon::at supplies the top vertices, including the cyclic last-to-first interval. The bottom two vertices are at the lower field limit. Every supplied horizon bin is preserved. A null profile explicitly falls back to zero degrees and displays a missing-DEM warning.

Mesh is an owned set of vertices and triangle indices, comparable to `std::vector<Vertex>` plus `std::vector<uint32_t>`. colored_vertex appends a position and opaque color; add_triangle appends three existing vertex indices. Painter::with_clip_rect returns a painter limited to the field. add(Shape::mesh(...)) submits the ground after the bodies. The scientific profile is not modified by clipping its display to the field.

## 4. Status and whole-period cards

The top status delegates the visible solar area to lunar_core::sun_fraction. Any positive fraction gives the green sunlight status; zero gives red. This estimates a potential sunlight supply, not panel output. The local horizon is evaluated at the body's center azimuth, the same approximation used by the core circular-segment area model. A strongly varying silhouette across a finite disk can therefore differ slightly from that center-tangent area estimate. Drawing a body does not replace the scientific predicate.

The Earth status uses the cached predicate `earth elevation > horizon + margin`, where the chosen margin is 0.5 through 1.0 degrees. It tests extra clearance for a radio signal, not whether any blue pixels remain visible. The small explanatory caption and help explicitly state this distinction: Earth may be visible but not pass the radio safety test. This is geometry, not a guaranteed communication service or a calculation of radio power.

The four cards cover the complete file interval, regardless of the currently selected path window. availability constructs a boolean solar series and calls lunar_core::stats with the existing Earth cache. A boolean is a true/false value, C++ bool. Each value is held over the next timestamp interval; the final endpoint adds no extra hour. Percentage is available duration divided by total duration, multiplied by 100. Longest night is consecutive unavailable duration, converted from hours to days by dividing by 24.

For example, at times 0 h, 1 h and 24 h with sunlight false, true, true, availability is 23/24 or 95.833333 percent, not two out of three samples. Longest night is one hour. The regression fixture also puts Earth at 0.75 degrees: a 0.5-degree margin permits communication, while 1.0 blocks it. The two summary results must follow that edit. Empty and malformed files remain explicit errors from SiteData::parse; no fake zero-valued summary is shown while loading or after failure.

Stats are cached at successful load and recomputed when the margin changes, not every globe animation frame. Changing the current time or path window does not change the whole-period cards. Successful loading also clamps a requested initial sample to the actual array length before indexing. Native launches may set MOON_SAMPLE_INDEX to a nonnegative sample number for reproducible starting times; absent or invalid values use zero. Browser launches use zero. This option affects presentation only.

## 5. Immediate mode and readable layout

Panorama owns the booleans help and technical plus the cached Stats value. Rust owns each value directly, like C++ members; no heap allocation or shared pointer is needed for these fields. Each frame redraws controls from that persistent state. Response::changed limits recomputation to an edited margin. A question-mark Button toggles help. Window::open borrows `&mut bool`, comparable to passing `bool&`, so closing the window updates the same persistent state. The help window scrolls and defines horizon, disk, degrees, UTC and the radio safety margin in ordinary English.

The text policy is explicitly Wrap. A vertical scrolling child can otherwise let a long caption increase its content width, hiding the north endpoint and slider value on a phone. The radio slider also reserves 125 logical points for its editable number and units and displays two decimals. This is separate from the horizontal time slider, which does not show an integer sample number. The summary Grid has two columns and four framed cards. Frame::group provides a background; it is not a new native window.

Desktop retains the existing side-by-side columns and black globe. At narrow widths the unchanged layout stacks the globe above the controls and permits vertical scrolling. Read the current status, change time, then inspect the strip and cards. The Technical view replaces the strip, not the controls or full-period statistics. The question-mark panel explains the limits: no relays, station availability, radio hardware, panel orientation, eclipses, temperature model or landing-safety assessment. Hourly samples can miss short events. Sunlight alone does not promise electrical power.

## 6. Checks and reproduction

Run workspace tests and clippy, a native release build, the wasm32-unknown-unknown app check, and trunk build --release from app/. Pure tests cover spherical disk radii, north wrapping, invalid/empty geometry, projection corners, weighted statistics, margin changes and existing parser/window errors. Native screenshots use the production binary with MOON_SAMPLE_INDEX=0 and 1138, corresponding to 2027-01-01 00:00 UTC and 2027-02-17 10:00 UTC. The latter has no visible solar area. These are selected states, not altered data.

Native rendering uses Mesa software GL; Chrome uses Pixel 7 emulation with device scale factor 2. These are not a physical phone or the user's GPU. Inspect the two native scenes and the phone screenshot for wrapping, north endpoint visibility, readable statuses and ground covering bodies. Browser checks require the selected C1 JSON and 2k texture pair to return HTTP 200, with no page or console errors. Preload-integrity and software-WebGL deprecation warnings are recorded separately from errors.

// Find a centered, clipped interval; precondition: validated nonempty sorted times and a valid index; C++ binary searches.
fn window(times: &[i64], index: usize, hours: i64) -> Range<usize>
{
	// Zero is an explicit entire-dataset choice, not a zero-duration plot; C++ early return.
	if hours == 0
	{
		return 0..times.len();
	}
	// Half of hours converted to seconds on each side of the current sample; C++ integer multiplication.
	let half = hours * 1800;
	// Include exact boundary samples; C++ lower_bound and upper_bound offsets.
	times.partition_point(|&t| t < times[index] - half)
		..times.partition_point(|&t| t <= times[index] + half)
}

// Split at a >180-degree jump, preserving time order; precondition: validated arrays/range; C++ vector<vector<point>>.
pub(crate) fn segments(track: &Track, range: Range<usize>) -> Vec<Vec<[f64; 2]>>
{
	// Own separate polylines rather than drawing a spurious chord across north; C++ nested vectors.
	let mut parts: Vec<Vec<[f64; 2]>> = Vec::new();
	// Visit only the chosen time samples; C++ counted loop over a half-open interval.
	for i in range
	{
		// Normalize an exact 360 endpoint to north before checking wraps; C++ positive modulo.
		let point = [
			f64::from(track.az_deg[i].rem_euclid(360.0)),
			f64::from(track.el_deg[i]),
		];
		// Start a new line for the first point or a seam crossing; C++ optional last-element tests.
		if parts
			.last()
			.and_then(|p| p.last())
			.is_none_or(|last| (last[0] - point[0]).abs() > 180.0)
		{
			// Seed this independent piece, including isolated samples; C++ emplace_back(vector{point}).
			parts.push(vec![point]);
		}
		// The previous branch guarantees a final part exists; C++ else with mutable vector back().
		else if let Some(part) = parts.last_mut()
		{
			// Append only adjacent non-wrapping samples; C++ push_back.
			part.push(point);
		}
	}
	// Move all pieces to the plot caller; C++ return by value.
	parts
}
